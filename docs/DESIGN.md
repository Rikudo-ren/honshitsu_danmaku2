# ゲームデザイン

## 一行で

> 攻撃できない。ただ避けて、時間が尽きるまで生き延びる。

原作小説に戦闘はない。あるのは**授業・配信・掲示板・時間**であり、
「残り時間が少ないほど、密度が上がる」という一行である。
本作はその一行をルールそのものにした弾幕ゲームである。

## 生存ループ

```
フェーズ開始（ボスが予備動作 → 引用表示 → 予告音）
   ↓  残り秒数が減る（右上に常時表示）
   ↓  パターンが重なっていく（レイヤはフェーズ内の 0s / 3s / 5s… で追加される）
   ↓  弾に当たる → 残機 -1、無敵時間、その場で復帰
   ↓  残り 10 秒 → 警告（音・画面枠の明滅・数字の色）
   ↓  0 秒 → フェーズ完了 → 次のフェーズ（弾を全消去して作り直す）
全フェーズ完了 → STAGE CLEAR
```

- **ボスに HP は無い。** 時間だけが進行条件である。撃つ手段が無いので当然である。
- 残機が尽きたら GAME OVER（その場でリトライ可）。
- 章の最後のフェーズだけ `tier: 'extra'` / `'final'` が付き、
  EASY では `phasesFor()` がそれを落とす（= EASY は 3 フェーズ）。

## 観測 — 唯一の干渉手段

| | |
|---|---|
| 溜まる | 弾に接近する（かすり）。`graze` 係数は EASY 1.0 / NORMAL 1.4 / HARD 1.8 |
| 満タン時 | 発動（X / Backspace、または画面右下のボタン） |
| 効果 | ボスが硬直（`flapStun`）＋ 自機近傍の弾を消去 |
| 制限 | 発動するとゲージは 0 に戻る。連発はできない |

原作の「観測」——櫻優の「好意は観測されていない状態で量子的に重ね合わさっている」
という主張と、零の「等高線は直接見えないが、サインを読むと存在がわかる」——
を、**攻撃しないゲームにおける唯一の干渉手段**として実装した。
危険を取る（近づく）ことでしか溜まらないので、これは「攻める」ではなく
「よく見る」という行為になる。

## 難易度

数値はすべて `src/game/difficulty.js` に集約している。

| | EASY | NORMAL | HARD |
|---|---|---|---|
| 同時弾数 `countMul` | 0.66 | 1.0 | 1.42 |
| 弾速 `speedMul` | 0.84 | 1.0 | 1.18 |
| 発射間隔 `intervalMul` | 1.34 | 1.0 | 0.78 |
| 軌道変化率 `turnRateMul` | 0.6 | 1.0 | 1.35 |
| 安全域 `safeZoneMul` | 1.42 | 1.0 | 0.76 |
| ボス移動速度 `bossMoveMul` | 0.82 | 1.0 | 1.16 |
| 残機 `lives` | 4 | 3 | 2 |
| 観測 `bombs` | 3 | 2 | 2 |
| 無敵時間 `invulnTime` | 3.2s | 2.6s | 2.0s |
| フェーズ数 `phaseCount` | 3 | 4 | 4 |
| 弾速上限 `speedCap` | 300 px/s | 340 px/s | 372 px/s |
| かすり係数 `grazeBonus` | 1.0 | 1.4 | 1.8 |
| 最終盤の密度 `denseFinale` | 0.7 | 1.0 | 1.0 |

**難易度は弾速では稼がない。** `speedCap` を超える弾は生成時にクランプされ、
`tools/playthrough.js` が毎フレーム全弾の速度を検査して上限違反を NG にする。
差は「同時数・間隔・軌道変化・安全域・ボスの動き・残機」で作る。

### `denseFinale` の扱い（設計上の注意）

`denseFinale` は最終盤のパターン（`finaleDense`）にだけ掛かるが、
そのパターンは既に `countMul`（同時数）と `intervalMul`（間隔）の影響を
受けている。HARD で 1.28 を掛けると**三重取り**になり、
実測で「8 回中 3 回しか生存できない」水準まで落ちたため 1.0 にした。
現在この係数は「EASY をさらに軽くする」ためだけのつまみである。

## 公平性の規則（実装されている不変条件）

1. **反応できない弾を出さない。**
   画面外から出す弾は必ず `spawnFromEdge()` を通り、`WarnMarker`（予告マーカー）が
   出てから弾が出る。レーザーは `interval ≥ warnDur + fireDur + gap` を守る。
2. **ボスは自分から近づきすぎない。**
   自機が画面下半分（`y > H*0.50`）に居るとき、ボスは 1 フレーム最大 6px で退避し、
   中心間距離 140px を下回らない。ボスの可動域は `y ∈ [H*0.12, H*0.42]` なので、
   自機が `y = H*0.50` に居るときの縦距離の最大は `182.4px` であり、
   140px なら常に 42.4px の余裕がある（**満たせない下限を設定しない**）。
   自機が自分から画面上部へ突っ込むのはプレイヤーの選択なので制限しない
   ——「上に行くと危険」は弾幕ゲームの基本の駆け引きである。
3. **瞬間死させない。** 被弾しても残機と無敵時間があり、その場で復帰する。
   フェーズ移行時は `invuln ≥ 1.5s` を保証する。
4. **弾数に上限がある。** `sys.maxBullets = 1400`。超えたら例外を投げて検証を止める
   （パフォーマンスを壊すほどの重ね掛けを構造的に禁止する）。
5. **同じ円形拡散を延々と撃たない。** 各フェーズは 2〜5 本のレイヤを持ち、
   時間差で追加・終了する。同一パターンの単独ループは存在しない。

## 描画順（可読性のための規則）

```
背景 → ボス → 予告線 → 弾グロー(加算) → 弾コア → レーザー → 予告マーカー
     → 自機 → エフェクト → HUD
```

**ボスは必ず弾より奥に描く。** 逆にすると、ボスの体と、その後ろに敷いている
暗い下地（背景に溶けないための alpha 0.62 の放射）が弾を隠してしまい、
見えない弾に当たる事故になる。弾の視認性はこのゲームで最も優先される性質なので、
ボスの見栄えより優先する。ボス自身が弾に隠れる問題は、後光（加算合成）と輪郭で担保する。

## カメラワーク

フェーズが切り替わる瞬間に、フィールド全体を最大 **5.5%** だけ寄せる
（`game.cam`）。1.1 秒かけて等倍に戻る。

- 「寄る」方向にだけ動かす。引くと画面の端に黒い隙間が出るため。
- 5.5% に制限しているのは、寄りすぎると視野が狭まって弾が見えにくくなるため。
  カメラは**可読性を損なわない範囲でしか動かさない**という方針。
- 掛かるのはフィールドだけで、HUD には掛からない。

## 状態遷移

```
boot
 └→ title ─→ diff ─→ stage ─→ stageintro（扉 → 会話）─→ ingame
     ↑                                                  ├→ pause ─→ ingame
     ├→ practice ─→ ingame                               ├→ gameover ─→ title / retry
     ├→ tutorial                                         ├→ results ─→ stage へ / title へ
     ├→ help / archive / records / options / credits      └→ allclear
```

`ingame` の内部はさらにフェーズ単位の状態を持つ:

```
intro（2.6s・ボス予備動作＋引用）→ active（残り秒数を消費）→ shift（1.9s・移行演出）
   → 次の intro … → clear（3.4s）→ results
```

## 保存

`localStorage` に 2 つ。壊れていても既定値で起動する。

| キー | 内容 |
|---|---|
| `honshitsu.save.v1` | 開放済みの章、クリア状況、ベスト記録、既読の会話・引用 |
| `honshitsu.options.v1` | 音量（全体 / 音楽 / 効果音）、ミュート、走査線、環境演出 |

章の続きから再開できる。練習モードでは任意のフェーズを単体で始められる。

## やらないこと（明示）

- 攻撃・ボムによるダメージ・アイテム回収による火力上昇は**入れない**。
  原作に無く、このゲームの主題（耐えること）を壊すため。
- 高得点狙いの周回を強制しない。スコアは記録するが、クリア条件ではない。
